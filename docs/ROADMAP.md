## What exists

IZ2 supports source-backed company/person directories, saved contracts,
relationship groups, immutable graph/analysis histories, deterministic review
priority, prepared-statement AI explanations, accounts and personal layouts.
The React workspace has EN/RU presentation; Swagger stays English. One Compose
file provides template, optional CPU/GPU model and HTTPS profiles.
Empty installation and source collection are separate operations.

The user accepted the explanation presentation and EN/RU interface, then requested
the current graphite direction. These are product decisions, not an independent
usability study or public-release approval. Documentation and bounded cleanup are
the current task; no new live collection or working-result regeneration is authorised.

## Next tasks in order

These are separate tasks, not actions started by this audit.

1. **Patch dependencies (AUD-010).** Resolve compatible frozen locks, triage current
   vendor advisories, run PostgreSQL/API/AI/frontend/image checks. Acceptance:
   applicable header/admin/provider issues have tested remediation; no untriaged
   relevant advisory remains before public exposure.
2. **Close collection correctness gaps (AUD-005–008).** Make rejected contracts
   repairable, define corrected verified-name policy, fence final run status and
   fix attempted/accepted counters. Acceptance: isolated PostgreSQL interruption,
   replacement-worker, name/conflict and counter checks preserve old evidence.
   Verify a current restore before algorithm changes.
3. **Fix restart and page-load recovery (AUD-021/022).** Capture the PostgreSQL
   restart exception and correct connection handling; add a recoverable state for
   failed lazy page downloads. Acceptance: repeated multi-worker restart checks
   produce no post-recovery 500, and a failed chunk offers useful reload/navigation
   without a loop or lost account/view state.
4. **Finish AI runtime provenance (AUD-012/015).** Enforce deadlines through slow
   headers/body/repair and capture resolved model digest/runtime. Acceptance:
   bounded cancellation, no late publication, digest-aware provenance/cache policy
   and safe fallback accounting. Review old prose separately.
5. **Automate release checks and operations (AUD-016/017).** Add clean CI using
   checked-in gates; bound native stdout logs and separate native collection from
   model availability. Acceptance: failure propagation, retained diagnostics,
   collection without a model and bounded disk growth.
6. **Demonstrate bounded convergence (AUD-009).** After explicit source permission,
   freeze scope and request budget; reconcile head/history/repair, restart recovery
   and source freshness. Acceptance: denominators and reasons for every gap,
   no lost rejected row and supported entitlement only. National completeness needs
   an authoritative reconciliation target.
7. **Improve large-graph and missing-record UX (AUD-013/014/020).** Measure a chosen
   workload before narrowing impact or moving layout work. Acceptance: documented
   latency/memory/readability budgets, stable histories, useful 404 navigation,
   keyboard/mobile saved-view checks.
8. **Prepare defence and target-host pilot.** Freeze a labelled demo and its actual
   research contribution, rehearse recovery, review public fields/source terms,
   then verify TLS/proxy/cookies, monitoring, resource bounds and off-host restore.
   Public rollout is a separate decision with a named operator and host.
